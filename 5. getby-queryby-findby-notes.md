
# React Testing Library - `getBy`, `queryBy`, `findBy` Detailed Notes

## Overview
This note summarizes how **different query function prefixes** in React Testing Library (`getBy`, `queryBy`, `findBy`) behave when attempting to find elements that do not exist.

We are focusing on how **prefixes** modify query function behavior, not the element types themselves. Example functions:
- `getByRole`
- `queryByRole`
- `findByRole`
- Variants like `getByText`, `queryByText`, `findByText` follow the same prefix rules.

---

## Component Used for Testing
```jsx
import { render, screen } from "@testing-library/react";

function ColorList() {
  return (
    <ul>
      <li>Red</li>
      <li>Blue</li>
      <li>Green</li>
    </ul>
  );
}

render(<ColorList />);
```

### Important Accessibility Details
- `<ul>` → **role**: `"list"` (1 element in DOM)
- `<li>` → **role**: `"listitem"` (3 elements in DOM)
- No text input elements → **no** element with role `"textbox"`.

---

## Goal
Understand how `getBy`, `queryBy`, and `findBy` behave when:
- **Element exists**
- **Element does not exist**
- **More than one element exists** (for `getBy`)

We specifically check role `"textbox"`, which **does not exist** in the component.

---

## 1. `getBy*` Behavior
### Key Points
- **Purpose**: Finds exactly **one** matching element.
- **If element not found OR more than one found → throws error immediately**.
- **Synchronous**: Runs instantly without waiting.

Example:
```js
screen.getByRole("textbox"); // throws error: no element found
```

### Test for Error Throwing
```js
expect(() => {
  screen.getByRole("textbox");
}).toThrow();
```

**Meaning**:  
- If no `"textbox"` role exists, test will pass because it’s expected to throw.
- If exactly one exists, it will return the element.
- If more than one exists, throws error.

---

## 2. `queryBy*` Behavior
### Key Points
- **Purpose**: Finds **at most one** matching element, **but does not throw error** if not found.
- **If element not found → returns `null`**.
- **Synchronous**: Runs instantly.

Example:
```js
const el = screen.queryByRole("textbox"); 
expect(el).toBeNull();
```

**Meaning**:  
Use `queryBy*` when:
- You expect element **might not exist**.
- You want to avoid exceptions breaking the test.

---

## 3. `findBy*` Behavior
### Key Points
- **Purpose**: Asynchronously find exactly **one** element.
- **If not found within timeout (default 1 second) → rejects Promise with error**.
- Polls DOM every ~50ms for updates (useful for waiting on async rendering).
- Must be `await`ed inside an **async test function**.

Example:
```js
await screen.findByRole("textbox"); // waits up to 1s, then rejects
```

### Testing `findBy*` Error Handling
Because `findBy*` returns a **Promise**, checking for errors is different:
```js
test("findByRole throws after timeout", async () => {
  let errorThrown = false;
  try {
    await screen.findByRole("textbox");
  } catch (err) {
    errorThrown = true;
  }
  expect(errorThrown).toBe(true);
});
```

**Meaning**:  
- If `"textbox"` appears within 1s, it returns the element.
- If not, it rejects and enters the `catch` block.

---

## Prefix Summary Table
| Prefix    | Synchronous? | If 0 elements | If >1 element | Notes |
|-----------|--------------|---------------|---------------|-------|
| `getBy*`  | ✅ Yes        | ❌ Throws     | ❌ Throws     | Use when you **must** have exactly one match |
| `queryBy*`| ✅ Yes        | ✅ Returns `null` | ❌ Throws     | Use when element **may not exist** |
| `findBy*` | ❌ No (Async) | ❌ Rejects Promise after timeout | ❌ Rejects Promise | Use for **async elements** appearing later |

---

## Additional Notes
- **All three** also have plural forms (`getAllBy*`, `queryAllBy*`, `findAllBy*`) which return arrays and differ slightly in error handling for empty results.
- These examples use `*ByRole`, but same logic applies to `*ByText`, `*ByLabelText`, `*ByPlaceholderText`, etc.
- Timeout for `findBy*` can be adjusted via RTL options:
```js
await screen.findByRole("textbox", {}, { timeout: 2000 }); // waits 2 seconds
```

---

## Best Practices
- Use `getBy*` when you **know** the element is there and want a hard fail if it's missing.
- Use `queryBy*` for **optional** elements where absence is acceptable.
- Use `findBy*` for **async content** that may appear after re-render or API fetch.
- Always handle errors when using async queries in tests.

---

## Quick Example Combining All
```js
test("demo of getBy/queryBy/findBy", async () => {
  render(<ColorList />);

  // getByRole - throws if not found
  expect(() => screen.getByRole("textbox")).toThrow();

  // queryByRole - returns null if not found
  expect(screen.queryByRole("textbox")).toBeNull();

  // findByRole - rejects if not found within 1s
  let errorThrown = false;
  try {
    await screen.findByRole("textbox");
  } catch {
    errorThrown = true;
  }
  expect(errorThrown).toBe(true);
});
```

---

## TL;DR
- `getBy*` → Immediate throw if not exactly one match.
- `queryBy*` → Immediate `null` if none found (still throws if >1).
- `findBy*` → Async, retries for 1s, rejects if not found.
