## 2. **Overall Testing Preference**

- **Always prefer** `ByRole` when possible.
- If `ByRole` is **not possible**, fall back to other queries:

  - `ByLabelText`
  - `ByPlaceholderText`
  - `ByTitle`
  - etc.

- **Avoid** `ByTestId` unless it’s absolutely necessary (last resort).

## 4. **Concept: Query Function Suffixes**

- **Suffix** = second half of a query method name.

  - Example: in `getByRole`, **"ByRole"** is the suffix.

- These suffixes define **criteria** for selecting DOM elements.

---

## 5. **Component for Testing – `DataForm`**

We build a form with various attributes so we can test all criteria.

### Imports:

```javascript
import { render, screen } from '@testing-library/react';
import { useState } from 'react';
```

### Component Structure:

```jsx
function DataForm() {
  const [email, setEmail] = useState('asda@asda.com');

  return (
    <form>
      <h3>Enter data</h3>

      <div data-testid='image-wrapper'>
        <img alt='data' src='data.jpeg' />
      </div>

      <label htmlFor='email'>Email</label>
      <input id='email' value={email} onChange={(e) => setEmail(e.target.value)} />

      <label htmlFor='color'>Color</label>
      <input id='color' placeholder='Red' />

      <button title='Click when ready to submit'>Submit</button>
    </form>
  );
}
```

---

## 6. **Special Attributes Added**

These props/attributes are **important for query selection**:

1. **`data-testid="image-wrapper"`**

   - Used for `ByTestId` (last resort).

2. **`alt="data"`** on `<img>`

   - Enables `getByAltText` queries.

3. **`placeholder="Red"`** on color input

   - Enables `getByPlaceholderText` queries.

4. **`title="Click when ready to submit"`** on button

   - Enables `getByTitle` queries.

5. **`label` + `htmlFor`** with matching `id` on inputs

   - Enables `getByLabelText` queries.

---

## 7. **Behavior of Special Attributes**

- **Placeholder text**:

  - Displays default text when input is empty.
  - Disappears when user types, reappears if cleared.

- **Title attribute**:

  - Any HTML element can have it.
  - Shows as a tooltip when hovering without clicking.

## 9. **Possible Query Function Suffixes**

Here’s when to use each:

| Query Method           | Criteria Used | Typical Use Case            |
| ---------------------- | ------------- | --------------------------- |
| `getByRole`            | ARIA role     | Most preferred, accessible  |
| `getByLabelText`       | Form label    | When label+input are paired |
| `getByPlaceholderText` | Placeholder   | Inputs with default hints   |
| `getByAltText`         | `alt` attr    | Images/media                |
| `getByTitle`           | `title` attr  | Tooltips                    |
| `getByDisplayValue`    | Current value | Form inputs with set value  |
| `getByTestId` _(last)_ | `data-testid` | Non-semantic, fallback only |

---

## 10. **Best Practices**

1. **Accessibility first**:
   Prefer queries that resemble how a user interacts with the page (e.g., role, label).
2. **Avoid brittle selectors**:
   Avoid relying on implementation details like `data-testid` unless required.
3. **Use semantic HTML**:
   Helps `ByRole` work naturally.
4. **Order of preference** (RTL recommendation):

   1. `ByRole`
   2. `ByLabelText`
   3. `ByPlaceholderText`
   4. `ByText` (for static text)
   5. `ByDisplayValue`
   6. `ByAltText`
   7. `ByTitle`
   8. `ByTestId`

---

## 11. **Key Takeaways**

- **`ByRole` is king**: Always start here.
- Use meaningful HTML attributes (`alt`, `title`, `placeholder`) to make queries more descriptive.
- `ByTestId` should be the **nuclear option**.
- Build components with testing in mind (semantic roles, proper labels).

---

## 12. **Extra Notes**

- **`ByRole` examples**:

  ```javascript
  screen.getByRole('button', { name: /submit/i });
  screen.getByRole('heading', { level: 3 });
  ```

- **`ByLabelText`** ties `<label>` to an `<input>` by `htmlFor` and `id`.
- **`ByAltText`** is often used for image-based UI verification.
- **`ByDisplayValue`** can check inputs’ bound state values.

This notebook is all about **how to select elements in RTL in a way that's close to how users perceive the UI**. Prefer semantic roles, then labels, then other accessible attributes, and keep `ByTestId` as a backup only.
