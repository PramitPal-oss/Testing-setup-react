# Accessible Names for Icon-Only Buttons (SVG) – Detailed Notes

## 📌 Context

- In many UI components, **icons are represented using SVG elements**.
- Sometimes a button contains **only an icon** (e.g., a close icon, sign-in icon) with no visible text.
- The usual method of setting an **accessible name** (via text inside the element) may not work in these cases.

---

## 1. **Problem Scenario**

- You have **two `<button>` elements**, each containing only an `<svg>` (no text content).
- These buttons are visually distinct because of their icons, but **screen readers cannot differentiate them** without additional context.
- In testing (React Testing Library), using `screen.getByRole('button')` will fail if there are multiple buttons, because:

  - **Multiple elements match the same role.**
  - Without an accessible name, they cannot be distinguished.

---

## 2. **Why It Happens**

- **Accessible names** are normally derived from:

  1. Text content of the element (most common).
  2. Associated `<label>` (for form controls).
  3. `aria-label` or `aria-labelledby` attributes.

- In icon-only buttons, there’s **no text content** to use.
- SVGs themselves **do not automatically provide an accessible name** unless specifically labeled.

---

## 3. **Solution – Using `aria-label`**

- **`aria-label`** is an HTML accessibility attribute used to assign an accessible name to an element.
- Syntax in JSX:

  ```jsx
  <button aria-label='Sign in'>
    <svg>...</svg>
  </button>
  ```

- **Important JSX note**:

  - Use lowercase `aria-label` exactly (not `ariaLabel` or `ARIA-Label`).
  - The dash syntax is **required** because JSX passes it as a standard HTML attribute.

---

## 4. **Example Implementation**

```jsx
function IconButtons() {
  return (
    <>
      <button aria-label='Sign in'>
        <svg>{/* Sign in icon */}</svg>
      </button>
      <button aria-label='Sign out'>
        <svg>{/* Sign out icon */}</svg>
      </button>
    </>
  );
}
```

---

## 5. **Testing with React Testing Library**

- You can now query each button **by role and accessible name**:

```javascript
const signInButton = screen.getByRole('button', { name: 'Sign in' });
const signOutButton = screen.getByRole('button', { name: 'Sign out' });

expect(signInButton).toBeInTheDocument();
expect(signOutButton).toBeInTheDocument();
```

- Without `aria-label`, this query would fail because both buttons would have no accessible name and be indistinguishable.

---

## 6. **Common Use Cases**

- **Icon-only buttons** are the #1 case where this happens:

  - Menu toggle buttons
  - Close (X) buttons
  - Media controls (play/pause)
  - Toolbar actions

- This approach is also useful when:

  - Space is limited (text is omitted for design reasons).
  - Text is redundant visually but still needed for screen readers.

---

## 7. **Additional Notes**

- **Why not use hidden text?**

  - You could include visually hidden text using CSS (`.sr-only`), but `aria-label` is cleaner in many cases.

- **Why `aria-label` is a "fallback":**

  - Best practice: provide visible text where possible for both accessibility and usability.
  - Use `aria-label` only when visible text is impractical or unnecessary.

- **Testing Tip:**
  Always confirm with `getByRole` and `{ name: '...' }` rather than relying on `getByText` for interactive elements. This ensures your tests match real accessibility behavior.
- **Screen Reader Benefit:**
  `aria-label` gives the button a meaningful name, so a screen reader might announce:

  > "Sign in, button"
  > instead of just
  > "Button"

---

## 8. **Summary Table**

| Situation                                 | Problem                                           | Solution                            |
| ----------------------------------------- | ------------------------------------------------- | ----------------------------------- |
| Button with visible text                  | Accessible name is derived from text              | No extra step needed                |
| Button with SVG only                      | No text → no accessible name                      | Add `aria-label="..."`              |
| Multiple identical-role elements in tests | `getByRole` returns multiple matches → test fails | Use `name` option with `aria-label` |

---

✅ **Rule of Thumb:**
If an element **doesn’t have visible text** but still needs to be identifiable by assistive technology or automated tests, **give it an `aria-label`** describing its purpose.
