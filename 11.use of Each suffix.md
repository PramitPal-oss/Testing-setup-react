# Detailed Notes: Query Functions in React Testing Library

This note summarizes **when to use each query suffix** in React Testing Library (RTL) and captures all details from the given transcript, plus additional clarifications for long-term recall.

---

## 1. **Overview of Query Functions in RTL**

In React Testing Library, query functions help locate elements in the rendered DOM during tests. These functions follow a **prefix + suffix** pattern:

### Common **Prefixes** (Search Strategy)

- **`getBy` / `getAllBy`**
  - Throws an error if no match is found.
  - Used when you expect the element **to be present**.
- **`queryBy` / `queryAllBy`**
  - Returns `null` if not found (no error).
  - Used when you expect the element **may or may not be present**.
- **`findBy` / `findAllBy`**
  - Returns a Promise, waits for element(s) to appear.
  - Used for **async operations** (e.g., elements appearing after fetch).

> **Rule of thumb:**
>
> - To prove **something exists and is visible** → use `getBy...`.
> - To check **something does not exist** → use `queryBy...`.
> - To wait for async changes → use `findBy...`.

### Common **Suffixes** (Search Criteria)

You can combine any prefix with any suffix:

- `getByRole`, `findByLabelText`, `queryByPlaceholderText`, etc.

---

## 2. **Suffix Functions and Use Cases**

### a) **`getByRole`**

- Finds elements by their ARIA role (`button`, `textbox`, `link`, etc.).
- Can filter by `name` (accessible name).
- **Preferred method** when role is known, as it’s closest to how users interact.

**Example:**

```js
screen.getByRole('button');
screen.getByRole('textbox', { name: /email/i });
```

---

### b) **`getByLabelText`**

- Finds a form element **associated with a label**.
- Works by matching the label's text, then finding the input it labels.

**Example:**

```js
screen.getByLabelText('Email');
```

---

### c) **`getByPlaceholderText`**

- Finds an input/textarea by its `placeholder` attribute.

**Example:**

```js
screen.getByPlaceholderText(/red/i);
```

---

### d) **`getByText`**

- Finds elements containing matching **text content**.
- Does not require knowing the element type.
- Useful when you only care about visible text.

**Example:**

```js
screen.getByText('Enter Data');
```

---

### e) **`getByDisplayValue`**

- Finds form elements by their **current value**.

**Example:**

```js
screen.getByDisplayValue('asda@asda.com');
```

---

### f) **`getByAltText`**

- Finds images (`<img>`, `<area>`, `<input type="image">`) by their `alt` attribute.

**Example:**

```js
screen.getByAltText('Data');
```

---

### g) **`getByTitle`**

- Finds elements by their `title` attribute.

**Example:**

```js
screen.getByTitle(/ready to submit/i);
```

---

### h) **`getByTestId`**

- Finds elements by `data-testid` attribute.
- **Fallback method** when no better semantic selector is possible.

**Example:**

```js
screen.getByTestId('image wrapper');
```

> **Note:** RTL discourages heavy use of `testId` — prefer semantic queries first.

---

## 3. **Choosing the Right Query**

### Priority (Recommended by RTL docs):

1. **`getByRole`** – Best for accessibility and realism.
2. **`getByLabelText`** – For form inputs.
3. **`getByPlaceholderText`** – If label not available.
4. **`getByText`** – For visible text checks.
5. **`getByDisplayValue`** – For form values.
6. **`getByAltText`** – For images.
7. **`getByTitle`** – Less common, use if above not possible.
8. **`getByTestId`** – Last resort.

---

## 4. **Regex Support**

Most query functions accept:

- **String** – exact match (case-sensitive).
- **Regex** – flexible match (can ignore case).
- **Function** – custom matching logic.

**Example with Regex:**

```js
// Case-insensitive text match
screen.getByText(/enter data/i);

// Partial text match
screen.getByTitle(/ready to submit/i);
```

## 6. **Tips & Reminders**

- `getBy` → for existence check (throws if not found).
- `queryBy` → for absence check (returns null).
- `findBy` → for async wait (returns Promise).
- Prefer semantic queries for accessibility alignment.
- Use regex to avoid brittle, exact-string matches.
- Avoid `testId` unless no semantic query works.

---

## 7. **Extra Recommendation**

While the transcript focuses on examples, in real-world tests:

- Prefer **user-centric** queries (`getByRole`, `getByLabelText`) over structural queries.
- Structure HTML with accessibility in mind — it makes testing easier and more robust.
- Use [`within`](https://testing-library.com/docs/queries/within/) to scope queries inside a specific container.
