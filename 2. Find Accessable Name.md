# Finding Elements by Accessible Name in React Testing Library

## **1. Problem Setup**

When writing tests using React Testing Library (RTL), we often use `getByRole` to find elements by their ARIA role.
Example:

```js
screen.getByRole('button');
```

However, **if there are multiple elements with the same role**, `getByRole` will throw an error:

- The expectation with `getByRole` is that exactly **one** element should be found.
- If multiple matching elements are found, RTL **fails the test** and lists all matching elements in the error message.

---

## **2. Example Component**

We create a component named **`AccessibleName`**.

```jsx
function AccessibleName() {
  return (
    <div>
      <button>Submit</button>
      <button>Cancel</button>
    </div>
  );
}
```

Here:

- **Both elements** are `<button>` elements → **Role:** `"button"`
- This causes `getByRole('button')` to return multiple matches → error.

---

## **3. Why This Happens**

- `getByRole` selects **all elements** with a matching role.
- Since we have two buttons, there’s **ambiguity**.
- RTL requires disambiguation when **more than one element has the same role**.

---

## **4. Solution — Filter by Accessible Name**

The **accessible name** is the label or text that assistive technologies (like screen readers) use to identify an element.

### **What is Accessible Name?**

- For elements with visible text (e.g., `<button>Submit</button>`), the accessible name **is the text content** ("Submit").
- For self-closing elements (e.g., `<input />`), it comes from attributes like:

  - `aria-label`
  - `aria-labelledby`
  - `<label>` element associated with it

---

### **Using Accessible Name in `getByRole`**

`getByRole` accepts a second argument — an options object.
The `name` property lets you specify the **accessible name**.

**Example:**

```js
const submitButton = screen.getByRole('button', { name: 'Submit' });
```

Here:

- `"Submit"` matches the button's accessible name.
- This **resolves ambiguity** — only one element matches.

---

## **5. Using Regular Expressions**

Instead of an exact string, you can use **regex** for flexibility.

Example:

```js
const submitButton = screen.getByRole('button', { name: /submit/i });
```

Why regex?

- `/submit/i` → case-insensitive match (`i` flag).
- Useful if casing might change (e.g., "SUBMIT", "Submit", "submit").

---

## **6. Full Test Example**

```js
test('can select by accessible name', () => {
  render(<AccessibleName />);

  const submitButton = screen.getByRole('button', { name: /submit/i });
  const cancelButton = screen.getByRole('button', { name: /cancel/i });

  expect(submitButton).toBeInTheDocument();
  expect(cancelButton).toBeInTheDocument();
});
```

---

## **7. Common Patterns and Tips**

- **Pattern:** Always combine `role` + `name` when there are multiple elements with the same role.
- **Regex:** Prefer regex with `i` flag for case-insensitive tests — helps prevent brittle tests.
- **Inputs:** Remember that for elements without visible text (like `<input>`), you must use attributes to define their accessible name.

---

## **8. Key Takeaways**

1. **`getByRole` fails** when more than one element matches the role.
2. **Accessible Name** helps disambiguate.
3. Use `{ name: '...' }` or `{ name: /.../i }` with `getByRole`.
4. Text inside an element = its accessible name (if visible).
5. Inputs and other non-text elements get their accessible name from labels or ARIA attributes.
