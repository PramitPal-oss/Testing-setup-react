# React Testing — Unexpected State Update & `act` Warning

## Context

When running React tests (especially those involving **data fetching** inside a `useEffect`), you may encounter **`act` warnings** in the terminal.  
These warnings are common in asynchronous scenarios and indicate that a state update happened **outside of the expected flow** in your test.

This note explains **why these warnings occur**, **why they are bad**, and gives an **example** scenario.

---

## 1. Why `act` Warnings Appear in Data Fetching Scenarios

- **`act`** is a helper in React Testing Library (and React DOM Test Utils) ensuring that all updates related to your test have been **applied before assertions**.
- In data fetching scenarios using `useEffect`, updates often happen **asynchronously**, leading to:
  - State changes _after_ your test's assertions.
  - Warnings like:
    > "Warning: An update to ComponentName inside a test was not wrapped in `act(...)`"

---

## 2. Four Topics to Understand This Problem

The video (transcript) outlines **four important topics** to understand `act` warnings.  
This note covers **the first one** in detail:

### **Topic 1: Unexpected State Updates in Tests**

- **Unexpected state update** means the state changes **after** you expect it to in your test’s flow.
- This is **bad** because:
  - Tests might fail when they should pass.
  - Tests might pass when they should fail.
  - It creates **flaky** tests (inconsistent results).

---

## 3. Example Scenario

Imagine a simple `UsersList` component:

### State Variables

1. `shouldLoad` — Boolean, determines whether data fetching should start.
2. `users` — Array of users fetched from a network request.

### Flow:

1. Initial render: `shouldLoad = false`, `users = []`.
2. User clicks a button → `shouldLoad` becomes `true`.
3. `useEffect` runs because `shouldLoad` changed.
4. Inside `useEffect`:
   - If `shouldLoad` is `true` → Call `fetchUsers()`.
   - When data returns → `setUsers(data)`.

---

## 4. Problem in the Test

Example test flow:

1. Render the component.
2. Find the button.
3. Simulate a click.
4. Immediately try to find all `<li>` elements for users.
   - ❌ At this moment, `fetchUsers()` is still pending (async).

Result:

- Assertion fails because **users have not been fetched yet**.
- Very shortly after, `fetchUsers()` completes and updates state → causing an **unexpected state update** after the assertion.

---

## 5. Why This Causes the `act` Warning

- The test **did not wait** for the asynchronous update to finish before checking the UI.
- React warns because:
  - The component updated **after** the test’s “interaction + assertion” sequence.
  - In real apps, this might be fine, but in tests, **timing mismatches break reliability**.

---

## 6. Takeaways

- Always wait for **asynchronous state updates** in tests.
- Use utilities like:
  - `await screen.findBy...()` — waits for the element to appear.
  - `waitFor()` — waits for a condition to be met.
- Never immediately assert after an async action — ensure the component has updated.

---

## 7. Key Concepts Recap

- **Unexpected State Update** → State changes after your expected point in the test.
- **Common in `useEffect` + data fetching** scenarios.
- **Bad** because:
  - Can cause false failures or false passes.
  - Creates flaky tests.
- **Fix**:
  - Use async-aware testing functions.
  - Wrap interactions in `act()` if necessary.
  - Let the test **wait for UI updates** before making assertions.
