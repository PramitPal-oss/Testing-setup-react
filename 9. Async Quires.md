# Detailed Notes on Async Queries in Testing

## Overview

This lesson focuses on when to use **`findAllBy`** (or generally `findBy` variants) in React Testing Library, particularly in scenarios involving asynchronous operations like **data fetching**.

---

## Key Scenario

- **Situation:** You want to ensure that certain elements **eventually** appear in the DOM after a delay (e.g., due to data fetching).
- **Typical Cause:** The elements you want to test are **not** rendered immediately after the component is mounted.
- **Solution:** Use `findBy` or `findAllBy` queries instead of `getBy` or `queryBy`.

---

## Example Component: `LoadableColorList`

This component simulates fetching data and rendering it later.

### Steps in the component:

1. **Simulate API call:**

   ```js
   function fakeFetchColors() {
     return Promise.resolve(['red', 'green', 'blue']);
   }
   ```

   - This mimics an API call using `Promise.resolve`.
   - Resolves immediately but still executes asynchronously (next microtask).

2. **State Initialization:**

   ```js
   const [colors, setColors] = useState([]);
   ```

3. **Fetching data in `useEffect`:**

   ```js
   useEffect(() => {
     fakeFetchColors().then((c) => setColors(c));
   }, []);
   ```

   - Empty dependency array ensures it runs only once after the first render.

4. **Rendering the list:**
   ```js
   const renderedColors = colors.map((color) => <li key={color}>{color}</li>);
   return <ul>{renderedColors}</ul>;
   ```

---

## Why `getAllBy` Fails Here

- **`getAllByRole('listitem')`** runs **immediately** after rendering the component.
- At this moment:
  - The **effect** hasn't yet updated the state.
  - Therefore, no `<li>` elements are present.
- **Result:** Throws an error: “No elements found with role listitem.”

---

## Why `findAllBy` Works

- `findAllByRole('listitem')`:
  - Returns a **Promise** that resolves when the elements appear in the DOM.
  - Automatically **retries** for up to **1 second** by default.
  - Stops as soon as the elements are found.

Example usage:

```js
test('findAllByRole waits for fetched elements', async () => {
  render(<LoadableColorList />);
  const els = await screen.findAllByRole('listitem');
  expect(els).toHaveLength(3);
});
```

---

## Key Differences Between Queries

### 1. `getBy...` / `getAllBy...`

- Synchronous.
- Fails immediately if element is not found.

### 2. `queryBy...` / `queryAllBy...`

- Synchronous.
- Returns `null` (or empty array) instead of throwing error.

### 3. `findBy...` / `findAllBy...`

- Asynchronous.
- Waits for element(s) to appear.
- Returns a **Promise**.

---

## Testing Tips

- **Async UI (Data fetching, delayed rendering):** Always use `findBy` / `findAllBy`.
- **Immediate UI (Static elements):** Use `getBy` / `getAllBy`.
- **Check absence without throwing errors:** Use `queryBy` / `queryAllBy`.

---

## Additional Notes

- Even though the Promise resolves instantly (`Promise.resolve`), React state updates are batched and applied asynchronously, so the DOM doesn't update instantly after `setState`.
- **Default timeout** for `findBy` queries: 1 second (can be customized).
- For complex cases, you can also use **`waitFor`** utility for more fine-grained waiting logic.

---

## Final Takeaway

- Use **`findBy` / `findAllBy`** for **async queries** when elements will appear **after a delay**.
- This prevents false negatives in tests caused by checking too early.
- Understanding when to use each query variant (`getBy`, `queryBy`, `findBy`) is essential for reliable testing.
