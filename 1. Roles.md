## Summary / Key takeaways

- This transcript walks through writing a unit test (using React Testing Library / Jest style) that queries almost every element in a sample component **by role**.
- The goal is to demonstrate how many HTML elements have _implicit ARIA roles_ and how to use `getByRole` (or `screen.getByRole`) to find them in tests.
- The approach used in the transcript:

  1. Render the example component under test.
  2. Define an array of role names (strings).
  3. Iterate over the role names and perform `screen.getByRole(role)` for each.
  4. Assert that each returned element is present with `expect(el).toBeInTheDocument()`.

- A failing case in the transcript demonstrates how React Testing Library prints the list of accessible roles when `getByRole` cannot find a match — this is how the author discovered they used the wrong role name (`"list group"`) for a `<ul>`; the correct role is `"list"`.
- Several role names are not obvious from their element names (`footer` → `contentinfo`, `header` → `banner`, `input[type=number]` → `spinbutton`). Memorize (or keep a reference) for occasional lookups.

## Reconstructed test — runnable example

> **Note:** This is a cleaned-up and runnable version reconstructed from the transcript's description. It uses correct API names and normalized role strings. Depending on the actual DOM produced by your `RoleExample` component you may need to adapt role names or use `getAllByRole` / `findByRole` / `queryByRole` instead.

```javascript
// RoleExample.test.js
import React from 'react';
import { render, screen } from '@testing-library/react';
import '@testing-library/jest-dom/extend-expect';
import RoleExample from './RoleExample'; // the component described in the transcript

test('can find elements by role', () => {
  // 1. render the component
  render(<RoleExample />);

  // 2. define an array of roles (normalized)
  const roles = [
    'link', // anchor
    'button', // button
    'contentinfo', // footer
    'heading', // h1/h2/h3
    'banner', // header
    'img', // image
    'checkbox', // input[type=checkbox]
    'spinbutton', // input[type=number]
    'radio', // input[type=radio]
    'textbox', // input[type=text], textarea
    'listitem', // li
    'list', // ul/ol
  ];

  // 3. iterate and assert that each role is present
  for (let role of roles) {
    const el = screen.getByRole(role);
    expect(el).toBeInTheDocument();
  }
});
```

**Notes on this example:**

- If an element for a role is missing or there are multiple elements with the same role, `getByRole` will throw. Use `getAllByRole` for multiple expected elements or `queryByRole` if you expect a role might not exist.
- If you want to assert on a specific labeled element, pass the `name` option: `screen.getByRole('button', { name: /submit/i })`.
