# 📜 Testing Library — Multiple Element Variations

## 1️⃣ Purpose of This Section

We are focusing on **query functions** that **return multiple elements** at once.
These are used when you intentionally expect **more than one match** for a query.

---

## 2️⃣ Multiple Elements Functions

When querying multiple elements, we use **plural forms** of the functions:

| Prefix Type    | Example Function               | Sync/Async      | Behavior                                   |
| -------------- | ------------------------------ | --------------- | ------------------------------------------ |
| **getAllBy**   | `screen.getAllByRole()`        | Sync            | Throws an error if **0 matches** found     |
| **queryAllBy** | `screen.queryAllByRole()`      | Sync            | Returns empty array if **0 matches** found |
| **findAllBy**  | `await screen.findAllByRole()` | Async (Promise) | Throws an error if **0 matches** found     |

---

## 3️⃣ Test Example Setup

- We render a component, e.g., `ColorList`.
- The goal is to **find all `<li>` elements** in it.
- We then check **how each function behaves**.

---

## 4️⃣ Detailed Behavior of Each Function

### **A. getAllBy**\*

```js
const listItems = screen.getAllByRole('listitem');
expect(listItems).toHaveLength(3);
```

- **Synchronous** → Returns array immediately.
- Throws an **error** if **no matching elements** are found.
- Great when you **expect multiple elements to always exist**.

---

### **B. queryAllBy**\*

```js
const listItems = screen.queryAllByRole('listitem');
expect(listItems).toHaveLength(3);
```

- **Synchronous** → Returns array immediately.
- If no elements found → **Returns `[]` (empty array)** instead of throwing error.
- Great when **elements might be missing** but you want to safely check.

---

### **C. findAllBy**\*

```js
const listItems = await screen.findAllByRole('listitem');
expect(listItems).toHaveLength(3);
```

- **Asynchronous** → Returns a **Promise**.
- Waits for elements to appear (based on `waitFor` internally).
- Throws an **error** if nothing appears within the timeout.
- Good for **dynamic content** (appears after async actions).

---

## 5️⃣ Example Test Structure

```js
test('Get all variations for list items', async () => {
  render(<ColorList />);

  // getAllByRole (sync, throws on zero)
  expect(screen.getAllByRole('listitem')).toHaveLength(3);

  // queryAllByRole (sync, empty array on zero)
  expect(screen.queryAllByRole('listitem')).toHaveLength(3);

  // findAllByRole (async, throws on zero)
  expect(await screen.findAllByRole('listitem')).toHaveLength(3);
});
```

---

## 6️⃣ Key Difference Summary

| Function        | Sync/Async | On **0 matches** | Use Case                                    |
| --------------- | ---------- | ---------------- | ------------------------------------------- |
| `getAllBy...`   | Sync       | Throws error     | Expect items **always present**             |
| `queryAllBy...` | Sync       | Empty array      | Items **might be missing**, want safe check |
| `findAllBy...`  | Async      | Throws error     | Expect async/dynamic rendering              |

---

## 7️⃣ Debug Tip

To verify that the test is actually running:

- Temporarily change `toHaveLength(3)` → `toHaveLength(2)`.
- You **should** see a failure in the test output.

---

## 8️⃣ When to Use Which

- **Static lists**: Use `getAllBy...` (fail fast if something’s wrong).
- **Optional lists**: Use `queryAllBy...` (no error if missing).
- **Async loading lists**: Use `findAllBy...` (waits until they appear).

---

## 9️⃣ Final Note on Error Handling

- `queryAllBy` → Never throws on **0 results**, just returns `[]`.
- `getAllBy` and `findAllBy` → Throw error if nothing found.

---

✅ **Rule of Thumb**:

> Use **get** for certainty, **query** for optional, **find** for async.
